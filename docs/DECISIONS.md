## Proposed in this kit
1. **Repo:** standalone `nevma-style` workspace (apps/web + apps/studio), like the TEMS kit. The Shopify/edition modules are framework-free so the Music repo can copy them for its Style block.
2. **Exactness:** CSS generated from the canvas and used unchanged; one component per block with `data-block`; fidelity tests (text, styles, height ±2 %, pixels ≤ 0.1 %) at 1440 and 390 are the definition of done.
3. **Commerce modes:** `COMMERCE_ENABLED=true` in production (`false` = emergency switch: no Shopify calls, notify-only) and `COMMERCE_MOCK` (fixtures reproducing the design, for local work and tests).
4. **Routes:** `/drops/<slug>`, `/pieces/<handle>`, `/pieces` (filters `?filter=available|coming|sold-out`, `?view=gallery`), `/categories/<slug>`, `/bag`, `/account/sign-in`, `/account`, `/account/orders|addresses|profile`, `/wishlist`, `/story`, `/client-care/<slug>`, `/legal/<slug>`. Tabs and filters are real URLs (work without JS, linkable).
5. **One colourway = one Shopify product = one Sanity piece.** The piece references the product synced by Sanity Connect (and keeps the handle for URLs and pre-launch pages). Size is the only option. A separate `piece` document (instead of editorial fields on the synced product) keeps the seed, coming pieces not yet in Shopify, and the fidelity fixtures independent of Shopify IDs.
6. **Edition rules and every stock sentence** in one tested module (COMMERCE.md §4). Edition size from a product metafield, default 5.
7. **Drop timing** by Shopify scheduled publishing to the Headless channel at `drop.opensAt`; Sanity holds the same date.
8. **One per customer** enforced in our cart only (quantity 1, second size replaces the first). Inside Shopify checkout it is not enforced on Basic; Terms allow cancelling extras.
9. **Sold while in bag:** lines re-checked on every bag render and before checkout; unavailable lines are removed from the Shopify cart and shown once as in the design.
10. **Accounts:** Shopify new customer accounts via the Customer Account API (PKCE). Our sign-in page collects the email and hands it to Shopify's hosted code page (`login_hint`); the designed code step is Shopify's page, branded.
11. **Edition numbers per order line** in an order metafield `nevma.numbers`, filled by staff at packing.
12. DECIDED 11 Nov (user): **no Supabase on Style.** Wishlist, notify-me, newsletter sign-ups, drop-alert/Moments preferences, contact messages and the alert log are Sanity documents written by the server with an Editor robot token (`formSubmission`, `customerProfile`, `alertLog`; IDs with a "." so they stay private), like the Music site's forms. The privacy notice now reads "Sanity (website content, wishlist and requests)" (design/build and the seed updated).
13. **Guest wishlist** in localStorage + `ns_wishlist` cookie, merged on sign-in.
14. **Interface wording** in `apps/web/src/content/ui.ts`; editorial copy in Sanity (singletons with typed fields per block, no page builder).
15. **Policy pages** as Portable Text with a renderer that outputs the design's exact `.s-prose` markup (paragraph, h3, bullets, notice, table).
16. **Emergency switch:** with `COMMERCE_ENABLED=false` the bag, account and wishlist icons are hidden and their routes return 404; piece states come from `phase1State`.
17. **Not designed, built from existing parts:** 404 (empty-bag pattern), `/drops` and `/categories` redirects, cookie consent panel (bag drawer pattern), order detail lives inside Orders (as designed), no search.
18. **Analytics:** Vercel Web Analytics after consent (matches the Cookies table "[Analytics] · With consent").
19. **Checkout, thank-you, payment-not-completed and Viva handoff** boards are branding references for Shopify and Viva, not Astro pages.
20. **Astro dev toolbar off** (`devToolbar.enabled: false`). Fidelity runs against `astro dev` because `@astrojs/vercel` has no `astro preview`; the fixed toolbar would paint over footer screenshots. The fidelity harness also hides `astro-dev-toolbar` in TEST_CSS.
21. **Repo-root `.env` mirrored onto `process.env` in `astro.config.mjs`.** Server modules use `serverEnv()` (plain `process.env`) so they work in vitest without `astro:env`. Astro/Vite alone leave secrets and many `PUBLIC_*` vars off `process.env` in SSR; without the mirror, Sanity stays "not configured" and pages fall back or 404.
22. **Piece buy form uses `display: contents`.** The design has size fieldset and Add button as separate `.s-buy` flex children (22px gap). Wrapping them in a real `<form>` for POST / no-JS would collapse that gap; `display: contents` keeps the form for submit while children stay in the buy-box flex. Noscript radio form lives outside `data-block="piece"` so it does not affect the fingerprint.
23. **Archive/category filter chips stay `<button>`** (design + fidelity fingerprint). Server still renders from `?filter` / `?view` / `/categories/<slug>`; `pieces.ts` switches instantly with `history.replaceState`. Category chips navigate via `data-href`. Both index and gallery lists are in the DOM for JS switching; inactive panels/rows use inline `display: none` because `.s-trio { display: grid }` overrides the `hidden` attribute.
24. **Live region copy is always “N pieces shown”** (design says “1 pieces shown”).
25. **Bag header badge under `bag-normal` / `bag-empty` fixtures is forced to 1.** Those design boards reuse shared chrome with a “1” badge that does not match the your-bag body (2 pieces / empty). Live carts and `bag-sold-while-in-bag` use the real available-line count.
26. **Fixture `signed-in` gates Customer Account data.** `getCustomer()` returns Alex only when `nv_fixture` includes `signed-in`; otherwise guest. Account side-nav always labels “Wishlist (2)” to match the boards (wishlist body lists 3).
27. **Customer Account session cookie `ns_session`** (encrypted JWE, HttpOnly, SameSite=Lax, 30 days). Middleware refreshes the access token when under 5 minutes remain. Create-mode name/prefs ride in `ns_create` (10 min) and apply on `/account/callback`.
28. **Cookie consent** uses the bag-drawer pattern (`.s-shade` / `.s-drw`), stored in `ns_consent` for 6 months. Analytics script loads only after opt-in. Auto-open is skipped when `navigator.webdriver` is set so fidelity screenshots stay clean; “Cookie settings” on `/legal/cookies` reopens the panel.
29. **Forms / email / crons (prompt 15).** Handlers live in `lib/server/form-handlers.ts` (Turnstile, honeypot, zod, rate limit → Sanity `formSubmission` → Resend). All reviewable copy is in `src/emails/copy.ts`; HTML shells in `layout.ts` / `templates.ts`. Crons: injectable jobs in `lib/server/jobs/*` + thin `/api/cron/*` routes gated by `CRON_SECRET`. Turnstile is skipped when `COMMERCE_MOCK=1` so no-JS fidelity/dev posts still work; production always verifies. `/api/revalidate` maps Sanity `_type`/`slug` to paths (plus `{ paths }` for crons). Real Resend smoke: `node apps/web/scripts/send-dev-email.mjs <you@…>` once `RESEND_API_KEY` + `MAIL_FROM` are set.
30. **SEO / analytics / perf (prompt 16).** `Base.astro` owns canonical, robots, OG/Twitter, and JSON-LD. Preview deploys (`VERCEL_ENV=preview|development`) and private routes (`/bag`, `/account*`, `/wishlist`, contact `?sent=1`) are `noindex`. Sitemap/robots/`llms.txt` are dynamic routes. Vercel Web Analytics loads only after `ns_consent` via `/_vercel/insights/script.js` (no pre-consent script). JS budget: `scripts/check-js-budget.mjs` (≤ 30 KB gz per page’s client entries) is part of `pnpm check`. Lighthouse mobile: `pnpm lighthouse` → `docs/reports/`. Local `astro dev` often misses LCP ≤ 2 s / perf ≥ 95 under mobile throttling; use `LH_SOFT=1` to archive the report, then re-run against a production/preview `SITE_URL` for the AC-14 gate.
